# 踩坑记录（Pitfalls & Troubleshooting）

从零逆向 DELTA-2C 过程中踩过的全部坑，按"症状 → 根因 → 结论"整理。
**每个坑都可能让后来者白耗几小时，先读这个。**

本项目是向 [kaiaai/LDS](https://github.com/kaiaai/LDS) 生态的贡献；
以下踩坑记录主要来自我们自己的解析器实现和调试经验。

---

## 1. 地图永远是圆形 —— 采样字节序写反（本项目最大的坑）

**症状**：无论雷达放哪、房间多大，地图永远是一个圆；"最远 9 点几米"恒定出现；换第二台雷达依旧。

**根因**：采样字节序是 `[q, d_hi, d_lo]`（质量字节在前，与 kaiaai 家族一致），但我们早期解析器误写成 `[d_hi, d_lo, q]`。质量字节 q≈0x90~0x97 被当成距离高字节：
- 一切真实距离被算成 `q×64mm ≈ 5.2~9.7m`；
- 无回波采样 `96 00 00`（真实 q=0x96、距离=0）被算成 `0x9600 → 4.8m`（±0.5 倍率时），**一圈全是假点 → 永久圆环**；
- 真实 2.6m 的墙被显示成 4.75m。

**验证方法**：拿已知距离的物体（手/身体/卷尺）做带标注的标定日志。手近=0.25m、胸膛=0.48m 一一对应即正确；若显示 9.2m/9.6m 就是字节序错了。

**结论**：解析时 `q = frame[pos]; d_mm = ((frame[pos+1]<<8)|frame[pos+2]) * 0.5`。

---

## 2. 距离比例 0.5mm/格 —— 与 kaiaai 家族其他成员不同

kaiaai 对 2A/2B/2D/2G 用 `distance × 0.25`。**2C 实测比例是 `× 0.5`**，与家族其他成员不同。若在 2C 上套用 0.25mm/格，会把房间整体缩小一倍（6m 墙显示 3m）。用带标注物体标定最可靠。

---

## 3. "11m 墙"是假象 —— 无回波饱和值

**症状**：小房间里测出 8~12m 的"墙"，且固定在最大量程处。

**根因**：无回波时不一定是 d=0。其中一台样机的无回波采样是饱和值 **~0x3FE0 = 16352 格 = 8.17m**。旧解析器把这类值当真实墙画进地图 → 永久"外墙"。

**结论**：房间 < 6m 时，任何 ≥ 8.17m 的读数都是无回波哨兵，直接丢弃。工具里统一 `d > 8000mm → 0`。

---

## 4. kaiaai / LDROBOT 官方驱动不认 2C

- kaiaai C++（LDS）/ Python（lds2d）校验 `protocol_version == 0x01`，2C 是 **0x13** → 拒收（kaiaai issue #16，作者未测过 2C）。
- LDROBOT 官方 SDK（ldlidar_sdk）只覆盖 LD06/LD19/LD14/LD14P，**不含 DELTA 系列**。
- 结论：不能指望现成驱动，用本仓库 `DeltaParser`。

---

## 5. 角度必须用起始/终止角插值

2C 帧里同时给了 `start_angle` 和 `end_angle`，采样 k 的角度 = `start + (end−start)×(k+0.5)/N`。kaiaai 2A 的均匀公式（`360/(16×N)`）对单帧近似可以，但 2C 每包的实际角跨在 20~23.5° 之间浮动，用协议自带字段最准。已用 LDROBOT 官方 STL（DTOF）协议文档交叉验证。

---

## 6. 电机电压决定数据形态（每台个体不同）

| 电压 | 转速 | 输出 |
|---|---|---|
| ~3.3V | ~9.3Hz | 只有 0xAE 转速帧 |
| 2.9V | ~7.9Hz | 出现 0xAD 测距帧 |
| **2.6V** | **~7Hz** | **最稳**（实测） |
| <2.5V | ~5Hz | 测距帧可能消失 |

转速与电压曲线**个体有差异**，换机器要重新扫电压。判断标准：调试 GUI 出现 0xAD 帧即可，不用严格追 7Hz。

---

## 7. VCC 必须 5V —— 3.3V 可能导致测距异常

官方规格最小量程 15cm。**逻辑供电必须 5V**；M+ M− 只是电机，2.5~3.3V。若发现近距测不到或少点，先检查 VCC 电压是否稳定。

## 9. 地图少角/扇区无回波 —— 摆放位置与死扇区，不是 bug

雷达在桌面上被 0.3~1m 杂物包围时，只有视线畅通的方向能看到墙，地图就只画出"一个角"。背面大扇区无回波通常是：雷达斜放（光束朝天）或背对门口/窗户。**搬到房间正中、水平、四周清空 1.5m** 再测。

---

## 10. 网页查看器改代码后必须重启进程

`lidar_webview.py` 的 HTML 由 Python 在启动时从内存提供，**改 HTML 只刷新浏览器没用，必须重启查看器进程**。残留进程会占 8080/8766 端口导致新实例起不来：

```bash
netstat -ano | grep -E ":8080|:8766"     # 找 PID
taskkill //PID <pid> //F
```

---

## 11. 另一台电脑识别不到串口

脚本靠 pyserial 枚举端口。新机器先装依赖，缺 pyserial 时下拉框是空的（已改为可手动输入 COM4）：

```bash
pip install pyserial websockets numpy pillow
python -c "import serial.tools.list_ports as lp; print([p.device for p in lp.comports()])"
```

多个 COM 口（主板自带 COM1/COM2 + 雷达 COM8）时查看器不会乱选，用启动器 GUI 显式指定。

---

## 12. 占用栅格建图的过滤规则

- `d < 0.15m`：低于规格最小量程的杂波读数，丢弃（不要把"杯子形"当物体）；
- `d > 8m`：无回波饱和，丢弃；
- `q == 0`：无效采样，丢弃；
- 光线投射（Bresenham）：原点到命中点=空闲，命中点=占用；0.05m/格、24m 见方。
- 静止雷达只能建静态地图；手持/小车移动建图需要里程计/IMU 做位姿跟踪（真正的 SLAM）。

---

## 13. 早期文档的教训

项目早期把该模组误判为 LDS01RR（XV11 协议，0xFA 帧），并写了错误调研报告。**判断型号要看协议本身，别被品牌标签/网络文章带偏**：2C 是 0xAA/0x13 帧、ToF 测距（GD32F330+TDC7201）+ dToF 避障，与 LDS01RR（0xFA/XV11）完全不同。网上 AI 生成的文章（如"小米雷达用三角测距"）有硬伤，只能取与实测吻合的数据点（采样率约 1800/s、设计转速 5~6Hz）。

## 调试速查

- 看协议解析对不对：`python analyze_delta2c_log.py logs/xxx_raw.log`（校验通过率 + 墙距直方图）
- 看单圈几何：`python render_scan_from_log.py logs/xxx_raw.log --accum`
- 手/胸标定：手凑近应在 ~0.25m、胸 ~0.48m 出平的近物段；若显示 9m+，回到坑 #1 检查字节序。
